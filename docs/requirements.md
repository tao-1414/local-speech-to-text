# 需求文档：Local AI Speech-to-Text Web Application

## 1. 需求理解

### 1.1 项目目标

构建一个基于 B/S（浏览器/服务器）架构的**本地**语音识别 Web 系统。用户通过浏览器麦克风录制语音，或上传本地音频文件，系统使用部署在本地的开源 AI 模型将中文或英文语音转换为文字，并在 Web 页面上展示识别结果。

核心特点：

- **本地推理**：ASR 模型在本地运行，不依赖任何云端语音识别 API。
- **CPU 推理**：必须支持在普通开发电脑（Windows 11 x64，普通 CPU）上运行，不强制要求 NVIDIA GPU / CUDA。
- **离线可用**：模型权重准备完成后，识别过程可在断开互联网的情况下运行（仅首次初始化允许联网下载模型）。
- **可复现**：通过统一的命令安装依赖、启动服务、运行测试。

### 1.2 用户与场景

| 用户 | 使用方式 | 场景 |
| ---- | -------- | ---- |
| 普通用户 | 浏览器麦克风录音 | 快速录入中英文语音并转文字 |
| 普通用户 | 上传本地音频文件 | 对已有音频文件（WAV 等）进行转写 |
| 开发/验收人员 | 调用 HTTP 接口 | 通过 `/health`、`/api/transcribe` 独立验证识别功能 |

### 1.3 目标与范围

**目标**：交付一个可实际运行、具备自动化测试、可独立复现的小型软件产品。

**范围内**：浏览器录音、音频上传、本地中英文识别、结果展示、异常处理、健康检查、自动化测试、真实模型验证。

**范围外（不要求实现）**：用户登录与权限、数据库存储、历史记录、说话人识别、音频降噪、语音翻译、TTS、模型训练/Fine-tuning、分布式部署、手机端适配、商业级实时字幕性能。

## 2. 功能拆分

### 2.1 功能总览

| 编号 | 功能 | 优先级 |
| ---- | ---- | ------ |
| F1 | 浏览器麦克风录音 | 必做 |
| F2 | 音频文件上传 | 必做 |
| F3 | 本地中英文语音识别 | 必做 |
| F4 | 识别结果展示 | 必做 |
| F5 | 异常处理 | 必做 |
| F6 | 实时语音识别 | 加分 |

### 2.2 F1 浏览器麦克风录音

1. 请求用户授予麦克风访问权限。
2. 点击 `Start Recording` 开始录音。
3. 点击 `Stop Recording` 结束录音。
4. 展示录音状态与录音时长。
5. 录音结束后，将音频提交至本地后端进行识别。

约束：

- 单次录音最长 **60 秒**。
- 录音过程中有明确的状态提示。
- 停止录音后才能发起该次完整识别（先录音后识别）。
- 录音失败或麦克风权限被拒绝时提示原因。
- 一次识别完成后可再次录音。

### 2.3 F2 音频文件上传

1. 支持上传本地音频文件进行识别。
2. 至少支持 **WAV** 格式。
3. 同时支持前端实际使用的浏览器录音格式（如 WebM/Opus 等）。
4. 文件上传与麦克风录音**共用后端识别逻辑**。
5. 对不支持的文件格式或无法解码的文件给出提示。

### 2.4 F3 本地中英文语音识别

1. 支持中文普通话识别。
2. 支持英语识别。
3. 用户可在页面选择中文（`zh`）或英文（`en`）识别模式。
4. 将识别文字返回给 Web 页面。
5. 一次识别完成后可继续识别下一段音频。

约束：

- 识别中文时输出中文文本，识别英文时输出英文文本，**不做语音翻译**。
- 中英文混合语音自动识别 / 自动语言检测为加分项。

**模型约束**：

- 必须使用本地运行的开源 AI 语音识别模型（如 faster-whisper、whisper 等，由实现时选型并说明理由）。
- 必须支持 **CPU 推理**，不能强制要求 NVIDIA GPU 或 CUDA。
- 允许首次安装/初始化时联网下载模型权重。
- 模型准备完成后，识别过程必须可在断网环境下运行。
- **禁止**调用 OpenAI、Azure、Google 等云端 ASR API。
- **禁止**使用浏览器 Web Speech Recognition API 替代本地模型推理。
- 应选择可在普通开发电脑 CPU 上运行的模型，不鼓励使用需要大量内存或特殊硬件的大型模型。

### 2.5 F4 识别结果展示

Web 页面需展示：

- 当前选择的识别语言。
- 录音 / 识别中 / 识别完成等状态。
- 识别完成后的文字内容。
- 音频时长（`duration_seconds`）。
- 识别处理耗时（`processing_seconds`）。

要求：

- 识别过程中页面有明确反馈，不出现长时间无提示。
- 用户能直接复制识别文字。

### 2.6 F5 异常处理

| 场景 | 预期行为 |
| ---- | -------- |
| 用户拒绝麦克风权限 | 提示权限问题，不导致页面崩溃 |
| 未检测到可用麦克风 | 显示明确错误 |
| 上传空文件或损坏音频 | 拒绝处理并返回错误信息 |
| 文件格式不受支持 | 返回明确提示 |
| 录音超过 60 秒 | 自动结束或明确限制录音 |
| 模型加载失败 | 返回可理解的失败信息 |
| 识别过程中后端出错 | 页面提示失败，允许重试 |
| 音频中没有可识别语音 | 不崩溃，返回空结果或明确提示 |

后端还需限制上传文件大小，建议上限 **10 MB**。

### 2.7 F6 实时语音识别（加分，可选）

在完成所有必做功能后实现：

1. 持续采集麦克风音频。
2. 将音频以分片或流式方式发送到后端。
3. 后端使用本地 ASR 模型处理音频。
4. 页面持续更新识别结果。
5. 点击停止后输出最终识别文本。

允许使用 WebSocket、HTTP 分片等合理技术；可通过短音频分片实现近实时识别，不要求模型原生流式推理，不设置毫秒级延迟要求。

## 3. 系统接口要求

### 3.1 接口清单

| Method | Endpoint | 功能 |
| ------ | -------- | ---- |
| GET | `/health` | 服务健康检查 |
| POST | `/api/transcribe` | 上传音频并识别 |
| GET | `/` | 打开 Web 页面 |

### 3.2 健康检查

```
GET /health
```

正常返回 HTTP 200：

```json
{ "status": "ok" }
```

### 3.3 语音识别接口

```
POST /api/transcribe
```

请求采用 `multipart/form-data`：

| 参数 | 类型 | 描述 |
| ---- | ---- | ---- |
| file | File | 音频文件 |
| language | String | `zh` 或 `en` |

返回格式：

```json
{
  "text": "你好，欢迎使用语音识别系统。",
  "language": "zh",
  "duration_seconds": 5.2,
  "processing_seconds": 1.8
}
```

字段说明：

- `text`：识别得到的文本。
- `language`：本次请求选择的识别语言。
- `duration_seconds`：音频实际时长。
- `processing_seconds`：服务端处理耗时（含必要的解码及模型推理，不含首次下载模型时间）。

错误处理：

- 非法参数或文件返回 HTTP 4xx。
- 模型服务不可用或推理失败返回 HTTP 5xx，并提供可理解的错误信息。

## 4. 技术前提与约束

### 4.1 技术环境

| 项目 | 要求 |
| ---- | ---- |
| 架构 | Browser / Server |
| 后端语言 | Python 3.12 |
| Web 框架 | FastAPI |
| 前端 | HTML / CSS / JavaScript |
| 浏览器 | Chrome / Edge 最新稳定版 |
| ASR | 开源、本地部署、支持中英文 |
| 推理 | CPU 必须支持，GPU 可选 |
| 自动化测试 | pytest |
| 依赖管理 | pip / requirements.txt |
| 统一复现环境 | Windows 11 x64，普通 CPU |
| 开发环境 | Windows、macOS、Linux 均可 |

### 4.2 禁止作为运行必要条件的组件

- Docker / Kubernetes
- Node.js / npm
- MySQL / PostgreSQL / Redis
- 云数据库或对象存储
- 云端语音识别服务
- CUDA / GPU
- 需面试官自行编译安装的特殊原生依赖

### 4.3 统一启动方式

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

访问 `http://127.0.0.1:8000`。默认通过 Chrome 使用 localhost 访问，不要求 HTTPS 或外部域名。

## 5. 测试要求

### 5.1 自动化测试覆盖范围

| 测试范围 | 测试内容 |
| -------- | -------- |
| HTTP API | 健康检查、正常请求、非法请求 |
| 音频处理 | 正常音频、空文件、无法解码文件 |
| 语言参数 | 中文、英文、非法语言 |
| 模型集成 | 模型调用、结果处理及异常情况 |
| 错误处理 | 不支持格式、模型失败等 |
| 前后端流程 | 至少验证实际录音或上传识别流程 |

要求：

- 区分 **Mock 测试**与**真实模型测试**。
- 允许在单元测试中模拟模型输出以加快速度。
- 必须额外提供使用真实本地模型的中英文识别验证，不能全部依赖 Mock 测试。

统一测试命令：

```bash
python -m pytest -q
```

该命令应能完成常规自动化测试，不依赖麦克风硬件，不因未下载模型而自动触发大规模模型下载。真实模型测试的执行方式单独提供并在 README 说明。

### 5.2 测试音频样本

- `samples/chinese.wav`：中文语音，5–15 秒，一至两句完整语音。
- `samples/english.wav`：英文语音，5–15 秒，一至两句完整语音。
- `samples/reference.txt`：对应人工参考文本。

音频应合法使用和分发，不包含敏感个人信息。

### 5.3 手动验证清单

1. 浏览器麦克风录制中文并识别。
2. 浏览器麦克风录制英文并识别。
3. 上传中文 WAV 文件并识别。
4. 上传英文 WAV 文件并识别。
5. 麦克风权限被拒绝时的系统表现。
6. 模型准备完成后，在无外网情况下完成识别。

将验证结果与已知问题记录在测试报告中。

## 6. 必要假设

1. 运行环境为 Windows 11 x64，普通 CPU，具备基础网络（仅首次下载模型需要）。
2. 使用 Chrome / Edge 最新稳定版浏览器访问 localhost。
3. 系统为单机单用户使用，不要求高并发或分布式能力。
4. 模型权重可在首次初始化时联网下载，此后识别在离线环境运行。
5. 单次录音上限 60 秒，上传文件上限约 10 MB，音频内容为普通话或英语语音（非翻译场景）。
6. 不要求手机端适配，页面按桌面浏览器设计。

---

## 7. 边界条件

1. **最长录音**：单次录音超过 60 秒需自动结束或明确限制。
2. **文件大小**：后端限制上传文件大小（约 10 MB），超限返回错误。
3. **文件格式**：至少支持 WAV 与浏览器录音格式；其余格式返回明确提示。
4. **空/损坏音频**：拒绝处理并返回错误信息，不崩溃。
5. **无语音内容**：返回空结果或明确提示，不崩溃；不得输出与音频无关的幻觉文本（如静音时的「字幕by索兰娅」）。
6. **语言参数**：仅接受 `zh` 与 `en`，非法值返回 4xx。
7. **模型不可用**：模型加载失败或推理失败返回可理解的 5xx 错误。
8. **权限拒绝**：麦克风权限被拒或未检测到麦克风时给出明确提示，不导致页面崩溃。
9. **离线运行**：模型权重准备完成后，识别流程不依赖网络。
